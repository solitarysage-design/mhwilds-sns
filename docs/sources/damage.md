## 出さないもの

- **秒あたり DPS は出さない。** 技の全長と各ヒットのフレームはモーションのデータ (motlist) にあるが、次の技へつなげるフレーム
  (キャンセル) が公開データに無く、見積もりしかないため (2026-10-24 の調査)。見積もりは灼熱化の判定の間隔を数えるのにだけ使う。
  代表コンボ 1 回の期待値と、その比 (スキルなし比・1 つ外したときの低下・Lv ごとの上昇) だけを出す。
- 1 ヒットごとの端数処理 (ゲーム内の切り捨て) はしない。期待値なので小数のまま足す。

## 属性の上限の読み方 (2026-10-21 に変更)

`elementRateLimit` (= `_ElementAttack_RateLimit` 2.3) と `elementAddLimit` (= `_ElementAttack_AddLimit` 40 → 表示 400) は、
**攻撃と同じく倍率と加算を別々に切る**: 属性値 = 元 × min(倍率の積, 2.3) + min(加算の和, 400)。

- 変えた理由: 物理側の `_PhysicalAttack_RateLimit` / `_PhysicalAttack_AddLimit` と同じ形の名前 (`〜_RateLimit` / `〜_AddLimit`) で並んでおり、
  物理側は「倍率の上限」「加算の上限」と読むのが自然。属性側だけ「2 つの上限の大きい方で合計を切る」と読む根拠が無い
  (前の読み `min(元 × 倍率 + 加算, max(元 + 400, 元 × 2.3))` は攻略サイトの説明に合わせたもので、ゲームデータの名前とは形が違う)。
  MHWS-in-json の加工データ (`damage_calculator`) も 4 つを `attackRateLimit` / `attackAddLimit` / `elementRateLimit` / `elementAddLimit` と
  同じ形で並べている (切り方のコードは公開されていない)。
- 確度 **medium**: ゲーム本体の計算 (`cHunterAttackPower.calcAttrPower`) の中身は見ていない。
- 実用上の差: 倍率の積が 2.3 を超えるか加算の和が 400 を超えるときだけ違う (例: 元 100・×3・+300 で 530 / 前の読みは 500)。
  今のスキル構成ではまず届かない。

## 条件つきスキルの発動率 (条件グループ)

発動率はスキルごとではなく**条件ごと**に `rules.conditionGroups` に持つ (定義は `tools/effects_conditions.py`)。
各スキルの `condition` (ゲーム内の説明文とゲームデータの値から書いた条件) を読み、同じ意味の条件を 1 つのグループにまとめた。

| グループ | 条件 | スキル | 既定の発動率 | 根拠 |
|---|---|---|---|---|
| `hpFull` | 体力が満タン | フルチャージ | 0.5 | 仮置き |
| `redHp` | 体力ゲージに赤い部分がある | 逆恨み | 0.5 | 仮置き |
| `hpLow` | 体力が 35% 以下 | 火事場力 | 0.5 | 仮置き |
| `enraged` | モンスターが怒っている | 挑戦者・巨戟龍の黙示録 | 1.0 | 本人の前提 (2026-10-22。基本発動する) |
| `chain` (段階) | 連撃: 未発動 / 1〜4 ヒット段 / 5 ヒット以降段 | 連撃・兇爪竜の力 | 1〜4 段 0 / 5 段以降 1.0 | 本人の前提 (2026-10-22。いつも 5 ヒット以降段) |
| `frenzy` (段階) | 狂竜症: かかっていない / 感染中 / 克服した後 | 黒蝕竜の力・無我の境地 | 感染中 0.5 / 克服後 0.5 | 仮置き |
| `beforeGuts` | 根性【果敢】がまだ発動していない | ヌシの魂 | 1.0 | 根性が発動するまでは常に有効 |
| `festival` | 季節の儀式の期間中 | 花舞/踊火/夢灯/祝謡の祈り | 1.0 | 期間中のみ (期間外は 0 にする) |
| `staminaFull` | スタミナ満タンをしばらく保っている | 渾身 | 1.0 | 本人の前提 (2026-10-22。基本発動する) |
| そのほか 16 個 | 力の解放・武器出し直後・ジャストガード後・ふきとばされた後・モンスターが毒か麻痺・状態異常を治した後・回避の後・巧撃中にもう一度回避・奇襲の後・坂をすべった後・自分が状態異常・鍔迫り合いの後 (闢獣)・拘束/凍結から回復か鍔迫り合いの後 (凍峰竜)・肉を食べた後・濡れている・追加の雷の後 | 1 条件 1 スキル | 0.5 | 仮置き |

- 「仮置き」= 根拠が無い。`placeholder: true` と `uptimeBasis` に書き、画面で人が入れる前提。探すタブの既定では 0% にして探す (20 個)。
- 「本人の前提」= 本人が決めた既定値 (2026-10-22 本人の決定「基本発動する前提で」)。`placeholder: false` で、`uptimeBasis` に
  「本人の前提 (2026-10-22): …」と、実際に起きない時間 (怒っていない・スタミナが減っている) と「下げたいときは上のスライダーで入れる」を
  書く (火力タブで、その条件のスライダーのすぐ下に出る)。連撃の当て始め・当てていない時間の回し方は `note` に書く (根拠の文のすぐ下に出る
  ので、根拠の文には重ねて書かない)。
  探すタブでもこの値で探す。本人が火力タブで発動率を入れたら、その値が優先 (ほかの条件と同じ)。
  2026-10-21 までは 3 つとも仮置き 0.5 で、探すタブの既定では 0% になり、挑戦者・連撃・渾身が探索で効かなかった。
- 同時に起きない条件 (`exclusiveWith`): 体力満タン ↔ 赤ゲージあり、体力満タン ↔ 35% 以下 (満タンなら赤ゲージも 35% 以下も無い)。
  赤ゲージありと 35% 以下は同時に起きてよい。計算では満タンでないときだけ赤ゲージ・35% 以下が起き、満タンでないときの中では独立とする
  (各条件の発動率は入れた値のまま。合計が 100% を超えたら、本人が入れた条件 → 根拠のある既定値 → 仮置き の順に保ち、
  仮置きなど後の方を減らして警告。2026-10-21 までは「データの並びで後の条件」を減らしていたので、仮置きの体力満タンが残り、
  本人の入れた赤ゲージ・35% 以下が減らされていた)。
- 狂竜症 (`frenzy`) は `sources` を持つ: 黒蝕竜の力を装備しておらず、相手も狂竜症を使わない (ゴア・マガラ・狂竜化した個体でない) ときは
  かかっていない 100% で計算する (無我の境地は効かない)。克服したときの会心 +15% (`rules.frenzyOvercomeAffinity`) は
  黒蝕竜の力 Lv1 の効果としてだけ入っている (スキルの外に出すかは未決)。
- 段階のある条件 (`categorical`): 連撃は `levels[]` の値 = 5 ヒット以降段、`byState.hit1to4` = 1〜4 ヒット段。
  兇爪竜の力は連撃が発動している段 (1〜4 段・5 段以降) ならいつでも。黒蝕竜の力は `byState.infected` = 感染中、主効果 = 克服後。
- 似ているが別のグループにしたもの: 闢獣の力 (鍔迫り合い・相殺の後 180 秒) と 凍峰竜の反逆 (拘束・凍結からの回復も含む・90 秒) は
  きっかけと時間が違う。千刃竜の闘志 (巧撃中にもう一度) は巧撃 (回避の後) の一部だが、別の条件として入れる (含まれる関係は計算に入れていない)。
- 未対応 (`supported: false`) の条件つきスキルはグループに入れていない (計算しないため)。
- 狂竜症を克服したときの会心 +15% (誰でも同じ) は黒蝕竜の力の効果としてだけ入れている。無我の境地だけのときは入らない (前と同じ)。

## 灼熱化 (火竜の力。2026-10-24 の調査で決めた仕様)

調査は 2026-10-24 (主張ごとに反証役 2 人)。確度は主張ごと。アプリの確度は low のまま (理由は「技のつなぎの秒数が見積もり」)。

| 項目 | 決めたこと | 確度 |
|---|---|---|
| 1 回のダメージ (上位) | Ⅰ = 固定 20 + 火 60 (内部値) × 火肉質/100、Ⅱ = 固定 40 + 火 120 × 火肉質/100 (`_ScorchingHeatData[7..10]`) | high |
| 火の分に掛かるもの | 火に効く属性スキル (`elementType` が火か無指定: 火属性攻撃強化・連撃・災禍転福・巨戟龍の黙示録) を **火の内部値 × 倍率 + 加算** (倍率が先) で。武器の属性の種類 (龍でも火でも) と関係なく掛かる。固定分には掛からない | high (TU4 後の実測で確かめられたのは火属性攻撃強化だけ。ほかは TU4 前の実測 87 値中 86 値一致。巨戟龍の黙示録は「無指定の属性強化は掛かる」の決まりに当てはめた推定) |
| 掛からないもの | 武器の攻撃力・武器の属性値・会心・会心撃【属性】・斬れ味 | high |
| 属性の上限 (倍率 2.3・加算 400) | 掛かるかは不明。**掛けない** (ふつうの装備では届かない) | — |
| 全体防御率・多人数の倍率 | ゲームデータで全部 1.0 → 計算に影響しない | high |
| 判定 | 対象ヒット (`additionalDamage` = RCOL の `_UseSkillAdditionalDamage`) でだけ判定する。前の判定から 2.4 秒 (`[0]`) たつまでは判定しない。**当たっても外れても** 判定のたびに待ちが始まる (TU4 前は 3.0 秒) | high |
| 対象でないヒット | 判定も待ちも起こさない | 前半 high・後半は実測なしの推定 |
| 判定ごとの発動 | 33% → 50% → 100% と上がり、発動すると 33% に戻る。長く見ると判定 2 回に 1 回 (平均 0.5。日本語の実測 100 回中 51〜53 回と一致)。計算は平均 0.5 (`perCheck`) | 段階の形は medium・平均 0.5 は high |
| `[3..6]` | 「別の読み」ではなく下位 (STORY ランク) の値とみられる: Ⅰ 固定 20 + 火 24、Ⅱ 固定 30 + 火 60。アプリは上位前提なので計算に使わず `extraDamage.lowRank` に残す | medium (下位の実測なし) |
| `_ViolentData` (= [2, 45, 85]) | 白熾の奔流ではなく **恨撃** (獄焔蛸の反逆) のもの。白熾の奔流は `_RyukiExplosion` (= [2.4, 33, 50, 100, …]) | medium |

計算 (`app/model/damage.js`): 灼熱化 = Σ (対象ヒット i) 0.5 × w_i × D_i。D_i = 固定 + (火 × 火の倍率 + 火の加算)/10 × そのヒットが当たる
火肉質/100 (傷口の段なら傷口の火肉質)。w_i = そのコンボを**繰り返したときの定常状態**で、ヒット i が判定になる割合 (`checkWeights`)。
判定の時刻は成否に関係しないので決定的に決まる: 時刻順に対象ヒットを見て、前の判定から 2.4 秒以上 (幅 1e-6 秒) なら判定。周の始まりの
「前の判定からの秒数」が前の周と同じに戻ったら、その間の平均を取る (時刻がフレームの倍数なので必ず戻る)。
前 (2026-10-23 まで) は「対象ヒットごとに確率 33%」で、待ちも火の属性スキルも入れていなかった。

### 技の時間 (つなぎの見積もり)

- 片手剣の技の長さと各ヒットのフレームは motlist にある (モーションごとの `frameCount` と、AttackCollision の `_RequestSetID` の区間。
  requestSetID は RCOL の `Wp01_Attack#N` / `Wp01_SubAttack#N` の番号と同じで、2 つの番号は重ならない)。再生の始まりは mct の既定の
  つなぎ (溜め斬り落としの 340 は 50f 目から、斬り上げの 306 は 5f 目から、反撃斬りの 329 は 15f 目から)。60fps と仮定 (medium。RE Engine の
  慣例・技の長さが自然)。
- **次の技へのつなぎ (キャンセル) のフレームはどこにも無い** → 見積もり (low): 判定が終わった次のフレーム〜+20f を目安に置いた
  (斜め斬り下ろしは +40f まで)。計算は mid。見積もった技と値 (フレーム。技の始まりから):

  3 段目の剣が 1、溜め斬り落としの斬り上げが 0.5。

  (ジャンプ斬りはモーションを決められないので 1.0 秒・時刻 0)。普段の△連携が 301 系か 255 系 (判定が 4〜11f 遅い) かはデータで決まらない。
  ヒットストップ (1 ヒットあたり数フレーム延びるはず) は入れていない。
- 調査の作業ファイル (リポの外): `motion_timing/hit_map.txt` (全ヒットとモーションの対応)・`cycle_est.py` (見積もりとコンボ 1 周)。
